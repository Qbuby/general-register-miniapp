# 测试说明

三层验证，覆盖面不同：

| 层 | 命令 | 数量 | 验证对象 |
| --- | --- | --- | --- |
| 单元 / 集成 | `npm test` | 60 | 通过 `fastify.inject()` 直接调用路由，使用临时 SQLite 库 |
| 小程序静态检查 | `node scripts/check-miniprogram.mjs` | 9 页面 / 50 文件 | 事件绑定、组件路径、页面完整性、JSON 合法性 |
| 端到端冒烟 | `npm run smoke` | 43 | 对真实 HTTP 服务、真实 SQLite 文件、真实 PNG 字节走验收场景 A–G |

## 一、自动化测试（`npm test`，60 项）

```
test/helpers.ts         每个测试文件独立的临时库与会话辅助
test/tenancy.test.ts    多租户隔离
test/registration.test.ts  动态报名表、校验、快照、状态门禁
test/capacity.test.ts   人数上限与并发
test/qrcode.test.ts     二维码稳定性与目标映射
test/export.test.ts     导出内容与安全
test/qr-production.test.ts  生产模式下拒绝输出不可用的二维码
```

每个测试文件在**独立进程**中运行，各自使用独立的临时数据库，可单独运行：

```bash
npx tsx --test test/tenancy.test.ts
```

### 关键用例

**多租户隔离**（`tenancy.test.ts`，13 项）
机构 B 逐个尝试访问机构 A 的机构资料、项目列表、项目详情、报名记录、导出、
报名状态修改、报名表、二维码；另有用例把机构 B 的 orgId 和机构 A 的 projectId
拼在一起，确认查询层的 `AND organization_id = ?` 拦得住。未登录与伪造 token 同样被拒。

**历史数据不被改写**（`registration.test.ts`）
提交一条报名 → 把表单改成「换标签 + 换顺序 + 删一个 + 加一个」→ 重新读取该记录，
断言姓名、电话、答案键值、以及快照里的字段名全部与提交时一致。

**并发名额**（`capacity.test.ts`）
5 个名额，同时发起 30 次提交（每次幂等键不同，因此不能靠幂等去重），
断言恰好 5 条 201、25 条 409 且 code 为 `project_full`，并且数据库中的实际条数是 5。

**导出**（`export.test.ts`）
验证表头含固定列与动态列、多选答案完整导出、已删除的历史字段仍以「（历史）」列导出、
以 `=` 开头的内容被转义、导出行为写入审计日志。

**二维码**（`qrcode.test.ts`）
验证 PNG 魔数、图片体积、目标页面路径、重复获取不换码、已下架项目扫码仍返回 200
并说明原因、把有效分享码拼到工作台接口后面拿不到任何数据。

## 二、小程序静态检查

```bash
node scripts/check-miniprogram.mjs
```

开发者工具不在 CI 里，但很多低级错误可以静态查出来：

- `app.json` 里声明的每个页面是否四件套齐全（`.js` `.json` `.wxml` `.wxss`）；
- 所有 JSON 是否可解析；
- WXML 里 `bind*` / `catch*` 绑定的事件名，在对应 JS 里是否存在同名方法
  （排除微信原生事件）；
- `usingComponents` 指向的组件路径是否存在（自动尝试省略的扩展名）。

这个检查在开发中确实抓到过问题：表单类型选择器原本在 WXML 里写了数组字面量
`range="{{['text','textarea',...]}}"`，WXML 不支持这种表达式，检查脚本在
开发者工具之外先把它暴露了出来。

## 三、端到端冒烟（`npm run smoke`）

```bash
# 终端 1
npm start
# 终端 2
npm run smoke
```

按验收标准逐条走一遍真实 HTTP 流程，输出每项的通过/失败，退出码 0 表示全通过。
它会创建带时间戳的机构与项目，不影响既有数据。

覆盖：服务可用性 → 场景 A（机构创建与隔离）→ B（项目发布与上下架）→
C/D（两级二维码）→ E（动态表单、校验、快照）→ F（报名管理、搜索、导出、
并发名额、截止时间）→ G（预览页与真实数据）。

最近一次运行结果：**43 项全部通过**。

### 人工验证过的界面

服务启动后用浏览器实际打开预览页确认过：

- 机构主页正确展示机构资料、介绍、在招项目卡片与联系方式；
- 项目详情页按该项目**自己的**表单渲染输入项（课程项目是「学员姓名 / 家长手机号 /
  当前年级 / 是否有编程基础 / 其他说明」，训练营项目是完全不同的一套）；
- 在浏览器中填写并提交，服务端校验通过后写入数据库，返回报名编号与机构联系方式；
- 直接 `curl` 一个必填项缺失的请求，返回 400 且指出具体字段
  （这正是「前端校验不能替代后端校验」的实证）。

## 四、尚未验证的部分

诚实起见，以下内容**没有**在真实环境跑过，代码已按官方接口实现但需要你用真实凭据验证：

1. `wx.login` → `jscode2session` 的真实往返（需要真实 AppID/AppSecret）；
2. `getwxacodeunlimit` 的真实调用与出图（同上）；
3. 小程序在微信开发者工具与真机上的运行；
4. 微信后台的 request 合法域名配置。

未配置凭据时，服务会明确降级为开发预览码并在接口、响应头、小程序界面三处标注，
不会伪装成「已生成可用小程序码」。
