# 二维码系统

二维码是本项目把线下宣传物料和线上招生连起来的主入口，因此单独说明。

## 两个层级

| 层级 | 对象 | 扫码后进入 | 小程序页面 |
| --- | --- | --- | --- |
| 机构主页码 | 每个机构一个 | 机构主页（介绍 + 在招项目列表） | `pages/org-home/index` |
| 项目详情码 | 每个项目一个 | 该项目详情页 + 报名表 | `pages/project-detail/index` |

项目码直达详情页，不会让公众先落到机构主页再自己找。

## 稳定分享码

每个机构 / 项目对应 `share_codes` 表里一行：

- `code`：12 位，从 `abcdefghijkmnpqrstuvwxyz23456789` 中随机生成（去掉了容易混淆的
  字符），长度控制在微信 `scene` 参数 32 字符的限制内。
- `kind`：`organization` 或 `project`。
- `organization_id` / `project_id`：目标。

**代码一经生成永不更换。** 「重新获取二维码」只是为同一个 `code` 重新生成图片，
因此印在海报、易拉宝、宣传单上的码不会因为后台操作而失效。

`share_codes` 上有两条部分唯一索引，保证一个机构只有一个机构码、一个项目只有一个项目码。

## 分享码不携带任何权限

码是公开的——它就印在传单上。它的作用只有一件事：**定位页面**。

- 公众接口 `GET /api/public/organizations/:code` 与
  `GET /api/public/projects/:code` 只做定位与只读查询。
- 机构工作台的每一个接口都要求 `Authorization: Bearer <token>`，
  并在 `requireMembership()` 里核对成员关系。
- 二维码图片本身也是受保护的：`GET /api/orgs/:orgId/qrcode.png` 未登录返回 401，
  机构 B 带自己的 token 去取机构 A 的码返回 404。

测试 `test/qrcode.test.ts` 里有一条用例专门验证：把有效分享码拼到工作台接口的查询串
后面（`?scene=<code>`），仍然拿不到任何管理数据。

## 扫码后的状态判定

所有状态都在**扫码那一刻**由服务端重新计算（`resolveSignupState()`），
不在二维码里编码任何状态。因此：

| 情况 | 扫码后看到 |
| --- | --- |
| 正常在招 | 完整详情 + 报名表 + 立即报名 |
| 机构未发布 | 提示机构主页尚未发布 |
| 项目未发布 / 已下架 | 详情照常展示，顶部标注原因，报名按钮禁用 |
| 机构暂停报名 | 提示已暂停 |
| 报名未开始 | 提示尚未开始 |
| 报名已截止 | 提示报名已截止 |
| 名额已满 | 提示名额已满 |

即使已下架或已截止，**印刷的二维码仍然有效**，只是落地页说明当前为什么不能报名。
对应的提交请求会被服务端再次拦截（409），返回具体原因而不是「系统错误」。

## 两种生成模式

### 正式模式（配置了 WX_APPID / WX_APPSECRET）

调用微信官方 `POST /wxa/getwxacodeunlimit`：

```json
{
  "scene": "<12 位分享码>",
  "page": "pages/project-detail/index",
  "check_path": false,
  "env_version": "release",
  "width": 1280
}
```

- `scene` 放分享码（小程序页面里从 `options.scene` 读取）。
- `check_path: false`：页面尚未发布到线上版本时也能出码，便于机构上线前先做物料。
- `width: 1280`：满足印刷分辨率。
- `access_token` 在服务端缓存，到期前 1 分钟刷新。
- 返回内容先校验 PNG 魔数；如果是 JSON 错误文档则翻译成明确的中文错误。

### 开发模式（未配置凭据）

**不会返回一个「看起来成功但扫不开小程序」的假码。** 开发环境下的具体做法：

- `GET /api/orgs/:orgId/qrcode` 返回 `mode: "preview"` 和一句 `warning`，
  明确说明「当前为开发预览码，扫码打开的是网页预览地址」。
- PNG 响应头带 `X-QR-Mode: preview`，小程序工作台据此显示黄色提示条。
- 二维码内容是 `https://<域名>/preview/p/<code>?t=<token>`，
  指向服务端渲染的预览页——它读的是**同一个数据库**，渲染的是公众真正会看到的内容，
  所以扫码 → 落地页 → 填表 → 提交落库这条链路可以被完整验证。
- 预览页需要 `PREVIEW_TOKEN`，不是公开页面。

**生产环境**（`NODE_ENV=production`）下预览码被禁用，两个接口的行为保持一致：

| 接口 | 响应 |
| --- | --- |
| `GET /api/orgs/:orgId/qrcode` | 503 `service_unavailable`，`details.missing` 列出缺失的环境变量 |
| `GET /api/orgs/:orgId/qrcode.png` | 503，不返回任何图片字节 |

不会出现「元数据说可以用、图却取不到」的矛盾。这条由 `test/qr-production.test.ts` 锁定。

配置好微信凭据后，同一个接口自动切回正式小程序码，页面上的提示随之消失，
**已印刷的码也不受影响**——因为分享码没变，只是承载它的载体从网页变成了小程序。

## 打印建议

- 建议最小尺寸 3cm × 3cm，四周留白不小于二维码宽度的 1/4。
- 小程序码本身就是黑白方块，导出为 PNG 后可以直接排版，不需要再处理。
- 机构码适合放门口、易拉宝、宣传单；项目码适合放具体活动的海报和朋友圈。
